## 评估器自身问题

首次批次 `.evals/experiment-development/` 因 Windows shell 超时留下孤儿 Node 进程、目录被占用而中断，只保留作诊断，不与正式批次合并。该批次也再次观察到原版用 say 返回目录列表而提前结束调度任务。

随后增加进程身份与后代跟踪、清理重试，以及将基础设施错误保留为单次失败。正式筛选又发现按全部历史 PID 逐个查询会超过清理时限；改为从当前存活进程查找属于试验的根进程，重复检查并校验创建时间。原故障的 34 条已记录程序在新控制器中离线重放通过，属于控制器验证，不是新模型试验。另验证孤儿进程清除后下一题继续，以及 80 个历史子进程正常清理。

生产 bash 自身在 Windows 下只终止 shell、可能遗留后代的问题仍在；评估器的外部终止不会被冒充为生产修复。

## 复用与边界

基础 20 题 × 3 次为 **60/60**，当前评分器版本基线保存在 `.evals/baseline-v3/`，默认 `npm run eval:regression` 已指向该基线。旧 `.evals/baseline/` 原样保留，不跨评估器指纹混用。

真实仓库 3 题 × 3 次的原始成绩为 **8/9**；唯一失败是给 tail 功能更新了 README，而题面只禁止修改根配置、原测试、包配置与锁文件。评分器额外限制了 README 和 LICENSE，属于未声明条件。修正后，同一批已记录判定为 **9/9**；未新增模型试验，没有改写任何功能、类型或兼容性断言，原 8/9 报告保留。

原始报告位于 `.evals/repository-control/`，修正版位于 `.evals/repository-control-reviewed/`，`regrade.json` 保存来源哈希、移除项与新任务哈希。另一个“正确实现并更新 README”的参考解已通过，用于校准合法替代解。后续使用 `npm run eval:verify -- <基线> <新报告>` 冻结所有已证明能力；该命令也检查 capability 题，不自动把探索题排除在回归门禁之外。

```sh
npm run eval:regression
npm run eval:repository -- --mode live --trials 3 --concurrency 3 --out .evals/repository-next
npm run eval:verify -- .evals/repository-control-reviewed/report.json .evals/repository-next/report.json
```

新增固定提交的真实仓库题、参考解、空答复和错误实现校准、两/四组对照、独立确认及预设提前停止。候选指纹包含本地静态依赖；评估器变更另有指纹，禁止把不同控制器的旧报告混作严格回归基线。

本轮原始记录、提示词、指纹和轨迹均在忽略目录 `.evals/`，未自动提交。`.env.local` 不进入快照或 worker 环境。上一批遗留临时目录的删除被自动审批策略阻止，目录保留；相关孤儿进程已终止。

验证：完整 `npm run check` 通过，307 项测试通过、1 项跳过，覆盖率 84.78%；另补计数器专项测试，保证引用代码或模型文本不会被误算成检查点执行。最终密钥扫描未在待提交文件中发现真实测试密钥，生产 `src/` 无本轮变更。

方法与复现命令见 [评估驱动的迭代](evaluation-iteration.md)。真实仓库题是有界任务，仍需后续覆盖更长的实际开发过程。
