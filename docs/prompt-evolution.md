# 首轮评估与 prompt 收缩

目标是保留 REPL、单 step 执行、say/deposit 两个通道与有意保留的全局状态，
清除说明性的长篇 prompt，再依据任务失败补回必要信息。

2026-10-26 使用本机 `.env.local` 中的真实模型完成了以下探索：

| 阶段                                                        | prompt 字符数 | 通过试验 |
| ----------------------------------------------------------- | ------------: | -------: |
| 原始 prompt                                                 |         11453 |    20/20 |
| 仅保留基础协议                                              |           507 |     9/20 |
| 补充观察通道与宿主 shell 说明                               |           867 |    15/20 |
| 明确纯 JavaScript、必须输出观察或最终答复，并提供观察例子   |          1021 |    20/20 |
| 同一短 prompt，harness 改为保留对象观察字段，每任务重复三次 |          1021 |    60/60 |

前三次失败暴露的普遍问题是：模型输出自然语言或包装格式，把 return/console 当成输出，
将中间观察交给 say 导致提前结束，以及在 Windows 上使用 Unix shell 语法。
只为这些已观察到的失败增加说明，没有加入任务文件名、答案或指定解法。

重复试验还发现，直接 `deposit(bashResult)` 会把结果转成 `[object Object]`，
隐藏 stderr 和退出码。这个问题由 harness 的值格式化解决，没有增加输出通道或改写调度原理。

任务设计也接受检验：`data/batch-files` 原先对 value 的描述可能指整个 JSON 对象，
现已明确要求源对象的数字 value 字段。任务指纹随之改变；上述探索阶段并非全部使用同一任务版本，
单次结果也不能证明统计意义上的改进。原始探索报告不作为当前正式回归门禁的基线。

最终基线包含 19 个 regression 任务与 1 个 capability 任务，每项三次独立试验：
60/60 通过，180 次模型请求，输入 181082 token、输出 96524 token。
输入数包含端点上报的缓存 token，不代表按统一单价计费的成本。并发为三，
其他预算使用默认值。这里只说明当前起始任务集与配置下的表现。

正式报告与完整轨迹保存在本机 `.evals/baseline/`；原始 prompt 和各轮探索报告保存在
`.evals/`，均未自动纳入版本控制。该基线不会被后续运行覆盖。
继续迭代时使用 [评估工作流](evaluations.md)，先检查评分与失败轨迹，再修改 prompt 或 harness。
